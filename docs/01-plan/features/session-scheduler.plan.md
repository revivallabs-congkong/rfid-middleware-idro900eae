## 1. Overview

### 1.1 Purpose

행사장에서 **하나의 리더/게이트가 시간대별로 다른 세션을 받는** 운영을 자동화한다.
예: A홀 입구가 09:00–10:30 "세션1", 10:30–12:00 "세션2" 체크인을 받는다.
현재는 운영자가 세션 전환 시점마다 콘솔에서 세션을 수동 재선택해야 한다. 이를
**시간표(스케줄) 파일**로 미리 정의해 두면 프로그램이 정해진 시각에 자동으로
해당 세션의 토큰으로 전환한다.

### 1.2 Background

- v0.2.x 는 **세션 카탈로그**(`pulse-sessions.json`, 세션 id·이름·토큰)를 받아
  운영자가 리더에 세션을 **수동 선택**하면 토큰을 config 에 기록한다(`applySession`).
- 세션 전환 시 대기(미전송) 기록 오배송을 막는 **rebind 가드**가 이미 있다
  (`GateSuspendedRebind` → operator resume: 전송/폐기 선택).
- 다게이트·다세션 행사에서 전환을 사람이 매번 맞추는 것은 실수·누락 위험이 크다.
- 토큰 보안 원칙: 실제 토큰은 저장소·로그·화면에 남기지 않고 카탈로그에만 존재.

## 2. Scope

### 2.1 In Scope

- [ ] **스케줄 파일 포맷 v1** 설계(외부에서 받아 쓰는 방식) — 여러 게이트의
      시간표를 한 파일로 일괄 관리, 토큰 비포함(세션 id 참조).
- [ ] **게이트 선택** UX: 스케줄 파일의 게이트 목록에서 이 인스턴스가 담당할
      게이트를 선택(세션 선택과 동일한 파일-선택/드롭다운 패턴 재사용).
- [ ] **운영 모드 선택**: `수동(manual)` / `스케줄(schedule)` 토글. 기본 manual.
- [ ] **스케줄 엔진**: 현재 시각이 속한 슬롯을 계산해 해당 세션 토큰을 적용,
      슬롯 경계에서 자동 전환(타이머). 프로그램 재시작 시 현재 시각 기준 재평가.
- [ ] **안전한 전환 오케스트레이션**: 전환 시 이전 세션의 대기 기록을 이전
      토큰으로 flush(그레이스) 후 새 토큰 적용 — 기존 rebind/resume 로직 재사용.
- [ ] **UI**: 모드 토글, 스케줄 파일 선택·게이트 선택, 오늘 타임라인·현재 슬롯·
      다음 전환 시각(카운트다운), 슬롯 공백(세션 없음) 표시.
- [ ] **검증·경고**: 슬롯 겹침/역순 거부, 참조 세션 id 가 카탈로그에 없으면 경고,
      NTP 시계 오차 시 스케줄 모드에서 경고 강조.
- [ ] congkong-v3 **서버 export 브리핑**(스케줄 파일 생성 양식) 문서.

### 2.2 Out of Scope

- 반복(매일·주간) 스케줄 — v1 은 행사용 **절대 일시(RFC3339)** 만.
- 한 인스턴스가 **여러 게이트**를 동시에 운용 — 인스턴스당 게이트 1개(리더 1개).
- 스케줄 파일에 **토큰 직접 포함** — v1 은 세션 id 참조(카탈로그가 토큰 단일 출처).
- 카탈로그+스케줄 **단일 통합 파일** — v1 은 두 파일 분리(토큰 격리 유지).
- 코어 파이프라인(큐·전송·분류 불변식) 변경 — 스케줄은 "언제 어떤 토큰을
  적용하는가"만 결정하는 부가 계층.
- 원격 제어/모바일 — 기존 원칙(127.0.0.1) 유지.

## 3. Requirements

### 3.1 Functional Requirements

| ID | 요구사항 |
|----|----------|
| FR-1 | 스케줄 파일(v1)을 파일 선택 또는 다운로드 자동 감지로 로드한다(카탈로그와 동일 UX). |
| FR-2 | 스케줄 파일은 여러 게이트를 담고, 운영자는 이 인스턴스의 담당 게이트 1개를 선택한다. |
| FR-3 | 운영 모드를 수동/스케줄 중 선택한다. 스케줄 모드에서 선택 게이트의 시간표를 따른다. |
| FR-4 | 현재 시각이 속한 슬롯의 세션 토큰(카탈로그에서 해석)을 자동 적용한다. |
| FR-5 | 슬롯 경계 시각에 자동으로 다음 세션으로 전환한다. |
| FR-6 | 전환 시 이전 세션 대기 기록을 이전 토큰으로 flush 후 새 토큰을 적용한다(오배송 방지). flush 실패 시 명시적 suspend 로 운영자에게 알린다. |
| FR-7 | 슬롯이 없는 시간(공백)에는 수집을 대기(세션 없음)로 두고 화면에 표시한다. |
| FR-8 | 프로그램/서비스 재시작 시 스케줄과 현재 시각으로 활성 세션을 재계산한다(상태 무의존). |
| FR-9 | 화면에 현재 세션·다음 전환 시각(카운트다운)·오늘 타임라인을 표시한다. |
| FR-10 | 스케줄 파일 검증: 슬롯 시간 겹침/역순 거부, 참조 세션 id 미존재·카탈로그 미로드 경고. |
| FR-11 | 스케줄 모드에서 NTP 시계 오차가 크면(기존 임계) 잘못된 세션 적용 위험을 경고한다. |

### 3.2 Non-Functional Requirements

- **토큰 격리**: 스케줄 파일에 토큰을 담지 않는다(세션 id 참조). 스케줄 파일은
  비밀이 아니므로 공유·버전관리 가능. 토큰은 카탈로그(`pulse-sessions.json`)에만.
- **결정성**: "현재 시각 → 활성 세션"은 순수 함수. 재시작·재기동에 무관하게 동일.
- **하위 호환**: 기본 manual 모드 = 현재 동작 그대로. 스케줄은 opt-in.
- **관측성**: 전환·공백·오차를 로그(`SCHEDULE_SWITCH`, `SCHEDULE_GAP`, `SCHEDULE_SKEW`)와
  화면에 남긴다.

### 3.3 스케줄 파일 포맷 (v1, 제안)

토큰 없음, 세션 id 참조. 여러 게이트 일괄. 시각은 RFC3339(오프셋 포함).

```json
{
  "version": 1,
  "eventName": "콩콩 컨퍼런스 - 이벤트 테크 리더",
  "exportedAt": "2026-09-10T08:00:00+09:00",
  "timezone": "Asia/Seoul",
  "gates": [
    {
      "gateId": "gate-a",
      "gateName": "A홀 입구",
      "slots": [
        { "sessionId": "session1", "start": "2026-09-10T09:00:00+09:00", "end": "2026-09-10T10:30:00+09:00" },
        { "sessionId": "session2", "start": "2026-09-10T10:30:00+09:00", "end": "2026-09-10T12:00:00+09:00" }
      ]
    },
    {
      "gateId": "gate-b",
      "gateName": "B홀 입구",
      "slots": [
        { "sessionId": "session3", "start": "2026-09-10T09:00:00+09:00", "end": "2026-09-10T12:00:00+09:00" }
      ]
    }
  ]
}
```

규칙:
- `version` ≠ 1 → 전체 거부(카탈로그와 동일 정책).
- 한 게이트 내 `slots` 는 시간 겹침 금지, `start < end`. 정렬·공백 허용(공백 = 세션 없음).
- `sessionId` 는 **카탈로그의 세션 id** 를 가리킨다. 토큰은 로드 시 카탈로그에서 해석.
- `gateId` 는 운영자가 인스턴스에서 선택하는 키(=리더에 바인딩). `gateName` 은 표시용.
- `timezone` 은 표시용(내부 계산은 각 시각의 오프셋으로 절대시각 처리).

> 대안 검토: (A) 세션 id 참조[채택] vs (B) 슬롯에 토큰 직접 포함. B 는 자기완결이나
> 토큰이 여러 파일에 흩어져 보안·유지 관리에 불리 → **A 채택**(토큰 단일 출처).

## 4. CTO 결정 (조사 요약)

1. **두 파일 분리 유지**: 카탈로그(세션·토큰) + 스케줄(게이트·시간·세션id). 스케줄은
   토큰 비포함 → 공유 가능. 토큰 보안 불변식 유지.
2. **기존 전환 로직 재사용**: 자동 전환 = "토큰 교체 + 대기 flush + resume". 이미
   `applySession`/`resume`/`QueueResume`/rebind 가드가 하는 일이다. 스케줄 엔진은
   "언제 어떤 세션으로 바꿀지"만 결정하고, 실제 교체는 기존 경로로 위임한다.
3. **상태 무의존 재계산**: 활성 세션은 (스케줄, now)의 순수 함수. 크래시/재부팅에
   강하고 무인 서비스 모드와도 호환. 이는 프로젝트의 "결정성" 원칙과 일치.
4. **모드는 config 플래그 + GUI 토글**: `operatingMode: manual|schedule`. manual 은
   현행 그대로(회귀 위험 0). 스케줄은 opt-in.
5. **게이트=리더 바인딩**: 인스턴스당 리더 1개 관례 유지. 선택한 `gateId` 가 그
   리더의 세션 소스가 된다(다중 게이트/인스턴스는 out of scope).
6. **시계 안전**: 스케줄은 절대시각. 잘못된 로컬 시계가 곧 잘못된 세션이므로, 스케줄
   모드에서 NTP 오차 경고를 격상(기존 `CLOCK_SKEW` 재사용).

## 5. Risks & Mitigations

| 리스크 | 영향 | 완화 |
|--------|------|------|
| 로컬 시계 오차 → 잘못된 세션 적용 | 잘못된 세션에 체크인 | 스케줄 모드에서 NTP 오차 경고 강조, 오차 크면 전환 보류·경고 |
| 전환 시 대기 기록 오배송 | 이전 세션 기록이 새 세션으로 감 | 전환 전 이전 토큰으로 flush(그레이스), 실패 시 suspend(운영자 resume) |
| 슬롯 경계에서 태그 몰림 | 경계 순간 귀속 애매 | flush 그레이스 동안 신규 적재 차단, 경계 처리 로깅 |
| 참조 세션 id 가 카탈로그에 없음 | 슬롯 비활성 | 로드 시 검증·경고, 해당 슬롯 공백 처리 |
| 스케줄 파일 핫 교체 | 진행 중 시간표 변경 | 재로드 시 현재 시각으로 재평가, 변경 배너 |
| 슬롯 공백 구간 | 수집 중단 구간 발생 | 화면에 "세션 없음(대기)" 명시, 다음 슬롯 시각 안내 |

## 7. Decisions (운영자 확인 완료 2026-09-03)

1. **슬롯 시각 기준** — ✅ **행사 당일 절대 일시(RFC3339)**. 반복(매일) 스케줄은
   범위 밖(§2.2 유지).
2. **공백 구간 정책** — ✅ **세션 없는 시간 = 수집 대기(off)**. 화면에 "세션
   없음(대기)" + 다음 슬롯 시각 표시(FR-7).
3. **전환 시 대기 기록** — ✅ **자동 flush(전송) 후 전환**. flush 실패 시에만
   suspend 로 운영자 개입(FR-6).

### 남은 확인 (Design 단계에서 확정)

4. **게이트 식별**: 스케줄 `gateId` 를 config 리더 id 와 동일 키로 둘지, 별도 매핑을 둘지.
5. **파일 배포**: 스케줄 파일도 카탈로그처럼 congkong-v3 콘솔에서 내려주는지(서버 브리핑 대상).
