# 리더 명령 응답·재접속 동작

> 리더에 명령(TCP write)을 보냈는데 응답(echo/ack)이 오지 않을 때의 처리 방식.
> SSOT 설계서 §6.4(`congkong-v3/docs/02-design/features/rfid-middleware-idro900eae.design.md`)의
> 구현 요약이다. 코드: `internal/reader/session/session.go`, `probe.go`.

## 1. echo/ack 가 필요한 것과 아닌 것

- **명령(요청 응답 필요)**: Stop(`3\r`), 버전(`>y v`), 부저·출력·RSSI 설정,
  인벤토리 시작(`>f`). 각각 기대 응답이 있다 — 예: 버전→`>v`, 인벤토리 시작→ack `>Af`.
- **태그 스트림(`>T`)**: 리더가 일방적으로 흘려보내는 데이터라 **echo/ack 개념이 없다.**
  아래 타임아웃 규칙은 태그가 아니라 **명령**에만 적용된다.

## 2. 한 명령의 처리 — `command()`

`internal/reader/session/session.go`의 `command()`가 명령 1건을 담당한다.

1. **write 데드라인 2초**: 명령을 쓸 때 2초 안에 나가지 못하면 `<명령> write 실패`로 종료.
2. **응답 데드라인 2초(`cmdTimeout`)**: write 후 응답을 기다린다. 그 사이 들어오는
   라인에서 기대 응답(matcher)을 찾고, 섞여 온 다른 라인(태그 등)은 버리며 계속 찾는다.
3. 세 갈래로 끝난다:
   - **응답 도착** → 성공, 다음 명령으로.
   - **2초 경과** → `"<명령> 응답 timeout"` 에러.
   - **연결 끊김**(read 오류) → `"<명령> 중 연결 종료"` 에러.

## 3. 핵심 원칙 — 재전송하지 않는다

타임아웃이 나면 **같은 명령을 다시 보내지 않고 세션 전체를 실패시킨다**(설계서 §6.4).

- 이유: 예컨대 인벤토리 시작(`>f`)이 리더엔 도달했는데 ack(`>Af`)만 유실된 경우,
  재전송하면 리더가 명령을 **중복 실행**할 수 있다.
- 그래서 "애매하면 재시도가 아니라 재연결" — 연결을 닫고 초기화를 처음부터 다시 한다.

## 4. 세션 실패 후 — `Run` 루프의 자동 복구

`command`가 에러를 반환하면 `serve`가 실패로 끝나고 `Run` 루프가:

1. 연결을 닫고 **`READER_DISCONNECTED`** 로그(message 에 사유 — 예: `INIT_VERSION 응답 timeout`).
2. **지수 백오프 재접속**: 1초 → 5초 → 30초(이후 30초 유지).
   인벤토리 진입에 한 번이라도 성공했던 세션이면 백오프를 0으로 리셋 → 1초 만에 재시도.
3. 재접속 성공 시 **초기화 시퀀스를 처음부터 재전송**:
   **Stop → 버전 → 부저 → 출력 → RSSI off → 인벤토리 시작**.
   - 맨 앞 Stop 은 리더가 자동 인벤토리(Reader Mode x=1) 상태일 때 접속 즉시 쏟아지는
     `>T` 스트림이 버전 응답(`>v`)을 묻어 timeout 을 유발하는 것을 막는다
     (실장비 관측 2026-09-02). Stop ack(`>A3`) 수신 또는 최대 ~0.7초 대기 후 진행하며,
     자동 인벤토리가 아니어도 무해하다.

## 5. 연결 생존 판정

- 판정 기준은 **연결/명령 응답**이다. 리더는 ping(ICMP)에 응답하지 않을 수 있어 ping 은 쓰지 않는다.
- TCP keepalive 는 OS 수준 dead-peer 감지 보조로만 켠다.

## 6. Probe (마법사 1단계)

`internal/reader/session/probe.go`의 `Probe()`는 현장 점검용 1회 진단이다 —
접속 → Stop → 버전 조회 → 종료. 같은 2초 타임아웃 규칙을 쓰되 **재접속 루프 없이**
1회만 시도하고 실패를 그대로 보고한다. 코어가 리더를 점유 중일 때는 호출하지 않고
status 의 `connState` 로 대체 판정한다(리더 TCP 단일 접속 제약).
